# v3 三端发布开发计划

## 目标

把《浮生牌局》从浏览器原型推进为同一内容版本、同一规则版本、同一天发布的三端产品：

- Windows 10/11 x64：Electron 安装包与可执行目录；
- iOS：Capacitor 原生工程，最终以 App Store 包发布；
- Android：Capacitor 原生工程，最终以 AAB 发布；
- 三端共享 React 界面、`GameState`、正式 reducer、内容数据、存档语义与视觉资产 ID；
- 允许移动端真机验收晚于 Windows 候选构建，但不允许移动端成为发布后的补丁项目。

本阶段的第一交付物是可启动、可完整游玩的 Windows 发布候选。iOS 与 Android 同步保持可构建工程，在获得 macOS/Xcode、Android SDK 和签名凭据后进入真机门。

## 制作原则

1. 规则只有一份。桌面和移动壳不得实现第二套资源、随机数或结算。
2. 视觉是内容，不是装饰。每个正式事件、困局和选择都必须引用稳定的视觉 ID；缺图会在内容校验中失败。
3. 移动优先检查构图。场景背景必须声明移动焦点，390×844 和窄屏横屏都要可读；选项保持纯文字，避免小屏重复缩略图。
4. 资源不能透支。任何明确扣除心气、余钱或人情的选择，资源不足时必须禁用并解释缺口。
5. 记忆决定叙事。离线出牌结果至少同时受记忆牌、做法、世界意图和胜负影响。
6. 自动平衡只找死路与异常，不替代真人对“有趣”和“公平”的判断。

## 里程碑与退出门

### M0 规则止血

- 负向资源变化自动成为可用条件；
- 不足原因在按钮内可见；
- 离线出牌结果引用具体记忆并按做法/胜负变化；
- 全量规则与组件测试通过。

状态：已完成。

### M1 三端骨架

- `desktop/main.cjs` 以 `contextIsolation + sandbox + no nodeIntegration` 运行；
- `npm run desktop:package` 生成 Windows x64 可执行目录；
- Playwright 真实启动 exe，进入正式故事；
- `android/`、`ios/` 与 `capacitor.config.ts` 同步同一 `dist/`；
- `npm run mobile:sync` 成功。

状态：已完成；移动原生编译仍属于M7真机门。

### M2 视觉垂直切片

- 锁定“档案里的电影静帧”风格；
- 标题、出身、一个成长事件三选项、组牌、一场困局、结案都有正式图片；
- 桌面采用画面/档案并置；手机采用上图下选择；
- 1440×900、390×844、窄屏横屏无关键信息遮挡；
- reduced-motion 下不依赖动画表达信息。

状态：已完成并扩展到现有全部剧情内容。

### M3 童年到身份

- 童年结束先展示成长总结与阶段去向；
- 时间跳切生成名校毕业生、职校技术员或灵活就业者，并列出三个主要形成原因；
- 身份不是价值评级，同一成长路线至少可形成两个身份；
- 不再从童年直接进入世界牌局。

状态：已完成。身份由实际牌册五类信号、成长倾向与资源生成；390px真实旅程已验证跳切。

### M4 全内容视觉迁移

- 每个成长事件有独立场景背景，选择项不重复展示缩略图；
- 每个成年事件和选择同样完整；
- 每场困局、世界意图与结案有背景或插图；
- 所有图片有桌面裁切与移动焦点元数据、替代文字和授权记录；
- 内容校验器拒绝缺失文件、重复 ID 和未声明移动焦点。

状态：现有14个成长事件、5个章节、合同原型、各牌局结案、15个成年事件、组牌与结局全部有图并有注册表测试；所有场景统一作为低对比、去色的叙事背景，选择项保持纯文字。注册表自动拒绝重复ID、缺图和缺少桌面/移动焦点元数据。

### M5 数值与叙事平衡

- 普通属性能完成五章；
- 1,000 个确定性种子批量检查身份分布、资源耗尽、选择锁死、章节胜负与卡牌使用；
- 不存在资源为零仍可付费、唯一显然最优牌或单身份死局；
- 每个身份至少 3 名目标玩家完成桌面试玩，再只修最高影响问题。

状态：自动部分已完成：1000个确定性完整人生无资源透支、无锁死，三身份可达且章节有胜有负；资源不足兜底与分牌叙事有单元测试。真人乐趣和平衡判断仍是公开发布前门槛，自动样本不冒充玩家证据。

### M6 Windows 发布候选

- `npm run verify:release` 全绿；
- 安装、首次启动、自动存档、刷新恢复、卸载均验证；
- 安装包、版本号、更新说明、隐私说明、图标和商店截图齐备；
- 正式公开前配置 Windows 代码签名证书。无证书的包只能称内部候选。

状态：界面收口候选源以 `v1.5.0-rc.5` 标记；安装器只允许从无改动且版本匹配的标签构建，并生成提交、标签与SHA-256绑定的发布清单。打包后EXE真实启动测试通过；安装器尚未签名，干净账户安装/升级/卸载仍是公开发布阻断。证据见 `DESKTOP_RELEASE_VALIDATION.md`。

### M7 iOS / Android 真机门

- Android：至少低端/主流各一台，竖屏和横屏，返回键、暂停恢复、系统字体、安装升级；
- iOS：至少一台小屏 iPhone 和一台刘海/灵动岛机型，安全区、后台恢复、系统字体；
- 两端检查内存峰值、首次图片解码、离线启动、存档升级和商店隐私清单；
- 完成签名 AAB / IPA、商店截图和审核说明后三端同日上线。

状态：工程、版本、图标、启动图和共享Web资产已同步；本机缺少JDK/Android SDK且不是macOS，尚未进入原生编译与真机门。执行清单见 `MOBILE_HANDOFF.md`。

## 发布质量门

```text
规则测试 → 组件测试 → Web E2E → 生产构建
        → Windows打包 → Windows exe E2E
        → Capacitor同步 → 内容/视觉校验
        → 桌面真人试玩 → 移动真机矩阵
        → 签名与商店审核 → 三端发布
```

任何一步失败都阻止升级版本。Windows 内部候选可以先生成，但在移动真机门完成前不宣布三端发布。

## 外部依赖

- Windows 公开发布：代码签名证书；
- Android：JDK 21、Android Studio/SDK、Google Play 开发者账号和签名密钥；
- iOS：macOS、Xcode、Apple Developer Program、证书与描述文件；
- 商店：隐私政策 URL、支持 URL、年龄分级、截图与审核说明。

这些是发布凭据和硬件门槛，不在源码中伪造，也不把“工程已生成”写成“移动包已验证”。
