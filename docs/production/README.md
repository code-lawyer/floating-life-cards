# 《浮生牌局》制作总计划

这套文档把产品设计转化为可以持续执行、测试和验收的制作流程。它面向没有游戏开发经验的创意策划，也作为执行制作、设计、程序、内容与质量工作的共同依据。

## 项目领导方式

- 用户担任创意策划：决定作品想表达什么、人物与事件是否真实、哪些社会题材值得写，以及关键创意分叉。
- Codex 担任执行制作人、主设计与技术负责人：主动拆解目标、排列优先级、编写规格、实现、测试、维护文档、报告风险并推进到下一可验证成果。
- 可逆且局部的决定由执行制作直接完成。
- 会改变作品核心体验、社会表达或造成大量返工的决定提交创意策划确认。
- 不因为缺少用户指令而停工；只要存在安全、明确、在范围内的下一步，就继续推进。

完整协作规则见 WORKING_AGREEMENT.md。

## 当前阶段

项目处于预制作阶段。

当前 v1 已经是一个可完整通关的技术原型，证明了：

- React 单页游戏可以稳定运行。
- 童年选择能够生成永久记忆牌。
- 成年困局、抽牌、回忆堆洗回和结局状态机能够闭环。
- 确定性随机、自动存档、移动端界面和基础测试可用。

v2 尚未证明的最大风险是：

> 成年牌局在不增加大量复杂规则的前提下，是否真的能提供足够的选择乐趣，并让玩家感到童年记忆正在回应成年生活。

因此不会先批量写30个童年事件。当前已完成一场可反复试玩的成年牌局原型、界面验收、浏览器自动化和决策空间分析，下一道门槛是真人规则试玩。

## 制作顺序

1. 制作基础设施：版本控制、可重复构建、任务清单和基线测试。
2. 成年牌局原型：永久记忆牌、回忆堆、身份被动、童年余温和一场完整困局。
3. 童年分岔原型：7–12岁动态事件和一次中学路线选择。
4. 垂直切片：从童年选择到时间跳切、起手身份和一场成年困局的完整体验。
5. 系统生产：补齐全部核心规则、存档迁移、教程和内容数据管线。
6. 内容生产：扩写完整童年、五个身份、五场成年困局和结局。
7. Alpha：功能完整，集中修错、平衡和补缺。
8. Beta与发布候选：真实玩家完整试玩、可用性、兼容性和发布检查。
9. 发布与维护：部署、版本记录、反馈处理和后续内容判断。

详细阶段门槛见 PIPELINE.md。

## 当前制作判断

- 产品方向已经足够清楚，成年牌局原型已进入验收，不需要继续无限讨论概念。
- 成年牌局是最高风险，必须先验证。
- 童年内容是最大工作量，必须等成年玩法成立后再规模生产。
- LLM不是核心路径，保持可选。
- 项目已有Git基线、独立v2原型分支和成人原型端到端测试；正式故事端到端覆盖、远端CI实跑与部署配置仍是制作基础设施缺口。
- 当前不承诺发布日期；先通过成年牌局和垂直切片两道门槛，再估算完整生产量。
- 成人原型结案页已能复制匿名客观记录，现场主持只需补记玩家理由、误判和感受；这降低记录成本，不替代真人样本。

## 每个开发周期的固定输出

一次开发周期必须产生：

- 一个可以运行或阅读的具体成果。
- 与风险相称的自动测试或人工验收记录。
- 更新后的任务状态和下一步。
- 若有设计变化，同步更新对应文档。
- 最多一至三个确实需要创意策划判断的问题。

只有文档、代码、测试和实际表现一致，任务才算完成。
