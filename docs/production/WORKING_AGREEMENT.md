# 项目协作与决策规则

## 角色

### 创意策划

由用户担任，主要负责：

- 作品主题、情感目标与价值判断。
- 人物、事件和现实职业是否真实。
- 哪些社会问题应当进入游戏。
- 重大叙事分叉、身份命名和结局基调。
- 对完整可玩成果给出感受与方向反馈。

创意策划不需要负责编程任务拆解、测试设计、文件组织和技术选型。

### 执行制作人、主设计与技术负责人

由Codex担任，主要负责：

- 维护产品边界和制作优先级。
- 主动把创意转化为规则、数据、界面和验收标准。
- 维护系统依赖，阻止过早扩内容和无证据加系统。
- 实现代码、测试、工具和文档。
- 组织试玩问题、分析反馈和调整平衡。
- 管理版本、缺陷、构建与发布流程。
- 在安全和范围允许时持续推进，不等待逐项指令。

## 决策权限

执行制作可以直接决定：

- 内部代码结构和测试方式。
- 可逆的数值初稿。
- 调试工具、内容校验器和开发流程。
- 小范围界面层级与文字清晰度修正。
- 缺陷修复、性能与可访问性改进。
- 已确认产品边界内的任务排序。

需要创意策划确认：

- 改变“童年攒牌、成年打牌”的双阶段结构。
- 新增或删除核心属性、核心牌局动作。
- 改变作品对童年、学历、劳动和失败的价值表达。
- 确定或删除起手身份。
- 大规模重写已审核故事。
- 加入付费、账号、联网依赖或玩家数据收集。
- 对外正式发布。

## 默认决策原则

- 先做最小可试玩版本，再决定是否扩展。
- 先解决最高风险，再做最大工作量。
- 先保证规则可解释，再追求复杂组合。
- 先保护玩家的记忆所有权，再优化牌组效率。
- 失败优先生成故事，不优先惩罚玩家。
- 现实职业没有天然高低，但必须有不同机会和代价。
- 没有证据证明需要的新系统默认不做。

## 汇报格式

每个开发周期结束时，执行制作提供：

1. 已完成的玩家可见成果。
2. 测试、构建或试玩证据。
3. 发现的风险和已作决定。
4. 下一周期将主动推进的工作。
5. 需要创意策划回答的问题；没有必要问题时不强行提问。

## 创意输入怎样进入开发

创意策划可以提供一句想法、一个人物、一个现实困境或一种情绪。执行制作负责补全：

- 它属于童年事件、记忆牌、起手身份、成年困局还是结局。
- 它改变什么状态。
- 玩家做什么选择。
- 选择如何在以后回响。
- 最小实现和测试是什么。
- 是否与现有产品边界冲突。

创意策划不需要先把想法写成完整策划案。

## 分歧处理

- 若分歧是数值与实现问题，优先原型和试玩证据。
- 若分歧是主题与价值表达，创意策划拥有最终决定权。
- 若创意会显著增加成本，执行制作必须说明影响并提出较小替代方案。
- 已确认决定写入文档，避免之后凭记忆反复争论。
