# 质量、试玩与发布计划

## 完成定义

一项功能只有同时满足以下条件才算完成：

- 玩家目标和规则已写清。
- 代码只在正确的领域模块实现，React不复制规则。
- 正常路径、边界和非法操作有相称的自动测试。
- 桌面与移动界面可完成。
- 键盘操作和基本辅助信息没有倒退。
- 构建通过，无未解释控制台错误。
- 文档与实际行为一致。
- 任务有验收证据。

## 自动测试层次

### 1. 纯规则单元测试

覆盖：

- 事件候选与确定性抽取。
- 路线开放与身份生成。
- 资源夹取。
- 卡牌分数、克制、组合、身份被动。
- 回忆堆、洗回和童年余温。
- 非法阶段命令返回原状态。

这些测试数量最多、运行最快，是每次改动的第一道门。

### 2. 完整流程状态测试

用固定种子从出生走到结局，验证：

- 不会卡在任何阶段。
- 记忆牌不会丢失。
- 五场困局与成年事件顺序合法。
- 普通属性而非作弊属性也能产生完整结局。
- 存档后的状态可继续。

### 3. 组件测试

覆盖：

- 选择反馈。
- 路线与身份说明。
- 组牌限制。
- 出牌预览和按钮状态。
- 设置、教程、确认和错误提示。

### 4. 浏览器端到端测试

至少覆盖：

- 桌面完整主路径。
- 390像素移动视口。
- 键盘完成主要操作。
- 刷新后恢复。
- 童年余温和回忆堆。
- 从时间跳切进入身份与成年困局。
- 控制台无错误。

当前自动覆盖成人原型、正式五章人生、童年回响、身份时间跳切、章节换牌、旧档迁移、刷新恢复，以及桌面/触摸/键盘辅助操作，并捕获页面和控制台错误。具体20条旅程及其边界见 `E2E_VALIDATION.md`；自动旅程不能替代真人对叙事与乐趣的判断。

### 5. 内容校验

构建时自动检查：

- 所有ID唯一。
- 引用的事件、身份、牌和标记存在。
- 所有选择有结果与记忆牌。
- 所有身份有优势、代价和困局标签。
- 所有困局有三类结果。
- 不存在永远无法满足的事件条件。
- 关键故事标记至少有一个后续用途。

## 平衡模拟

模拟器不评价叙事，只寻找系统异常。

初始观察指标：

- 三种首发身份的生成分布。
- 三种成长路线的开放与选择分布。
- 每章越过、带代价继续和改变题目的比例。
- 心气归零发生年龄。
- 每张牌的携带率、抽到率和使用率。
- 三种倾向的平均得分贡献。
- 童年余温使用时机与召回对象。
- 哪些事件选择长期压倒其他选项。

首轮警戒线：

- 任一起手身份在大量合理策略样本中低于5%，需要检查是否近乎不可达。
- 任一童年选择在无叙事偏好时成为80%以上的数值最优解，需要重新权衡。
- 超过20%的普通策略人生在第三场困局前因心气归零结束，需要降低早期死亡螺旋。
- 某一类牌长期占全部出牌的55%以上，需要检查组合和困局覆盖。
- 童年余温多数场次完全不值得使用，说明主题机制没有进入策略层。

这些是诊断线，不是最终玩家KPI。

当前成人合同原型已能穷举合法唤起、换手和童年余温分支，报告每个身份与固定开局的可胜/可败性、推进范围和最短胜利轮数。它只覆盖当前固定困局；完整人生仍需抽样策略模拟而非穷举，详见 `PROTOTYPE_BALANCE_ANALYSIS.md`。

## 真人试玩

### 规则试玩

对象：3–5名愿意思考规则的玩家。

重点：

- 是否理解牌会回来。
- 是否能预测出牌结果。
- 是否出现真正的取舍。
- 是否理解身份被动。

阶段1不计算平均满意度。三份样本的有效性、硬门槛、记忆内容进入决策、真人实际路线分化、2/3核心门槛、身份表达安全否决和调整后重新取样规则见 `PLAYTEST_SYNTHESIS.md`。

### 垂直切片试玩

对象：5–10名目标玩家。

重点：

- 童年选择是否与成年身份有可感知因果。
- 时间跳切是否自然。
- 是否愿意开始第二局。
- 文本与规则是否争夺注意力。

### Beta试玩

对象：20–30名未参与设计的玩家。

重点：

- 完整通关。
- 移动端与存档可靠性。
- 教程理解。
- 身份是否被感知为高低等级。
- 哪些事件令人共鸣或不适。

## 试玩记录

不只问“好不好玩”。记录：

- 玩家在每个页面停留和犹豫的位置。
- 玩家用自己的话解释规则。
- 玩家为何选择某张牌。
- 玩家误以为什么会发生。
- 玩家主动提到的记忆与人物。
- 玩家想重开的原因。

观察到的行为优先于事后评价。

成人原型结案页可以复制或下载一份本机生成的客观Markdown，减少人工抄录构建版本、身份、种子、资源、工具使用和逐轮分数的成本。该记录不联网、不采集个人信息，也不推断玩家理由；规则解释、犹豫、误判和情感反馈仍由观察者逐字记录。不同构建版本的样本不得直接合并。

三份客观记录齐备后，`npm run validate:playtest -- <证据目录>` 检查份数、构建版本、匿名编号、三个身份、声明回合数和逐轮事实字段。无效批次返回非零状态。命令行传入目录内的Markdown，校验器只按标题识别客观记录；观察笔记分类后被忽略，不解析字段、不输出内容，也不能判定玩法是否通过。

## 错误等级

- 阻断：无法继续、存档丢失、白屏、错误结局。立即修复。
- 严重：规则结算错误、身份生成错误、卡牌永久丢失。进入当前周期。
- 一般：反馈不清、布局问题、文案不一致。按影响排序。
- 轻微：纯装饰、极少出现且无后果。集中处理。

## 发布质量门槛

- 全部自动测试通过。
- 生产构建通过。
- 正式环境桌面与移动主路径通过。
- 无已知阻断和严重错误。
- 存档版本、重置和损坏恢复通过。
- 所有三种首发身份至少完成一次人工通关。
- 打印档案不缺路线、身份和关键记忆。
- LLM端点关闭时游戏仍完整可玩。
- 依赖、第三方内容、隐私和版权说明完成。
- 有版本号、更新说明、反馈方式与回滚方案。

### 三端发布补充门

- Windows：真实启动打包后EXE；在干净账户完成安装、首次启动、存档恢复与卸载；公开包必须有代码签名。
- Android：`package.json`版本同步到`versionName`，签名AAB在低端与主流真机验证竖/横屏、返回键、暂停恢复、离线启动和存档升级。
- iOS：同版本归档IPA，在小屏与刘海/灵动岛真机验证安全区、横竖屏、后台恢复、离线启动和存档升级。
- 三端使用同一`dist/`、规则reducer、内容和视觉注册；平台壳不能复制或修改牌力与资源规则。
- 390×844自动旅程必须在触摸仿真环境验证剧情图真实解码、无横向溢出、44像素触控目标和身份跳切；844×390窄屏横屏也必须通过同类视觉与触控检查。真机门仍不能被浏览器仿真替代。
- 1000种子完整人生只用于发现资源透支、身份不可达、死循环与结算异常，不作为胜率、乐趣或身份表达通过证据。
