# 成年困局真人试玩主持手册

> 目标：用同一个 `1.4.0` 构建完成三名目标玩家的规则试玩，观察理解与选择，不教玩家怎样赢。

## 样本与分配

| 记录编号 | 起手身份 | 建议玩家背景 |
| --- | --- | --- |
| P1-01 | 名校毕业生 | 不限卡牌经验 |
| P1-02 | 职校技术员 | 不限卡牌经验 |
| P1-03 | 灵活就业者 | 不限卡牌经验 |

- 玩家应当没有参与本原型的设计。
- 尽量包含至少一名从未玩过卡组构筑游戏的玩家。
- 不记录姓名和联系方式；只使用记录编号。
- 开始前说明观察者会记录游戏行为和部分原话，征得玩家同意。

## 启动试玩构建

首次使用，在项目目录运行：

```powershell
npm ci
```

每次主持时运行：

```powershell
npm run playtest
```

这条命令会先生成生产构建，再显示两个地址：

- `Local`：在主持人的电脑上打开。
- `Network`：同一可信 Wi-Fi 内的手机或电脑打开；若防火墙询问，只允许“专用网络”。不要在公共 Wi-Fi 上开放。

若终端没有显示 `Network` 地址，就让玩家使用主持人的电脑，不临时安装穿透或公网分享工具。试玩结束按 `Ctrl+C`，确认终端回到命令提示符。

## 每位玩家的流程

1. 打开标题页，确认分配的身份入口可见。
2. 只告诉玩家：“请解决这场合同困局。页面上的信息都可以使用。”
3. 第一次出牌前，请玩家用自己的话解释目标、世界意图、倒计时、身份被动和牌会去哪里。
4. 玩家操作时不要解释克制、惯用手、三式、换手或童年余温；只追问“你现在在考虑什么？”
5. 逐轮记录玩家首先注意到的牌、最终选择、另一张候选牌、理由与误判。
6. 结案后按 `PLAYTEST_TEMPLATE.md` 的顺序访谈，不先问“好不好玩”。
7. 在结案页保存客观记录：
   - 本机 `localhost` 可以点“复制本局试玩记录”；
   - 通过局域网地址访问时，优先点“下载本局试玩记录”，避免浏览器拒绝非安全来源的剪贴板权限。
8. 检查记录内的“构建版本”为 `1.4.0`，文件名包含本次身份；将其与观察笔记放在同一个记录编号下。
9. 点击“返回标题，换一个身份”，再交给下一位玩家。

## 立即中止并上报

以下情况不继续凑样本：

- 页面白屏、无法继续或结案按钮消失。
- 记忆牌永久丢失、结算分数与预览不一致。
- 玩家遭遇明显不适并希望停止。
- 导出的身份、轮次或构建版本与页面不一致。

记录复现步骤和客观文件，由执行制作先处理阻断问题；修复后升级构建版本，旧版本样本不与新版本混合。

## 阶段1有效样本

一份样本只有同时满足以下条件才计入：

- 玩家独立完成或明确选择停止，不由主持人代打。
- 主持人没有提前解释策略。
- 有玩家自己的规则解释和至少两轮选择理由。
- 有结案客观记录，或因阻断中止时有明确复现步骤。
- 记录包含构建版本和匿名编号。

三份样本齐备后，只汇总重复出现、影响最大的一个问题；偏好差异不直接进入开发任务。
