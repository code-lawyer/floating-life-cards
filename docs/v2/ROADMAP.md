# v2 开发路线图

本文件保留v2玩法里程碑。跨越制作基础、预制作、垂直切片、Alpha、Beta和发布的完整阶段门槛，统一以 [制作总计划](../production/README.md) 与 [完整制作流程](../production/PIPELINE.md) 为准。

## 原则

先验证成年牌局是否有趣，再扩写童年内容。童年事件数量最大，但成年牌局是风险最高的设计问题；如果记忆在成年时没有产生有意义的选择，增加更多童年文本只会放大返工。

## 里程碑 0：文档基线

目标：

- 确认产品不使用 MBTI，也不制作完整人生模拟。
- 确认时间跳切与首版起手身份池。
- 确认成年牌局保持单卡回合还是增加有限双牌回应。
- 用两至三个完整因果案例检验术语。

验收：

- PRODUCT、GAME_DESIGN、CONTENT_GUIDE 与 CONTEXT 无相互矛盾。
- 所有未确认选择列在本文末尾，不伪装成既定需求。

## 里程碑 1：成年牌局原型

范围：

- 使用现有 10 张固定记忆牌。
- 实现 3 个起手身份。
- 实现 1 场求职或工作困局。
- 将弃牌文案改为回忆堆。
- 实现每场一次童年余温。

验收：

- 玩家明确知道卡牌不会永久消失。
- 至少存在两种可解释的有效打法。
- 童年余温既有战术价值，也能产生情感回响。
- 一场困局在不阅读外部规则文档时可以完成。

## 里程碑 2：童年分岔原型

范围：

- 只实现 7–12 岁六个年度事件。
- 候选池不少于 12 个事件。
- 实现普通、重点、技能倾向三种中学路线。
- 用牌标签、境遇和关键标记共同判定。

验收：

- 相同小学选择能够明显改变中学事件池。
- 三条路线没有单向强弱排序。
- 玩家能从总结页看懂自己为何进入该路线。

## 里程碑 3：时间跳切与起手身份

范围：

- 补齐 4–17 岁童年流程。
- 实现首版 5 个起手身份。
- 为每个身份编写一段可解释的时间跳切。
- 允许不同成长路线汇入同一身份，也允许同一路线分化。

验收：

- 身份不是由单一属性或单个随机事件决定。
- 玩家可以追溯至少三个形成身份的原因。
- 每个身份同时有优势、代价和可被成年选择改变的空间。

## 里程碑 4：完整成年篇

范围：

- 5 场成年困局。
- 每场 1–2 个成年选择事件。
- 身份差异化开场与事件权重。
- 三类困局结果和完整结局档案。

验收：

- 普通数值下完整流程不会频繁陷入不可逆失败。
- 同一牌册在不同身份和局势下有不同组合价值。
- 失败会改变故事，但不会删除人生或要求读档。

## 里程碑 5：平衡、可用性与发布准备

- 批量种子模拟。
- 5–10 名玩家的完整试玩。
- 移动端、键盘与屏幕阅读反馈检查。
- 存档版本升级与损坏恢复。
- 文本校对、打印档案和性能检查。

## 当前待决定事项

### 1. 成年牌局出牌数量

默认方案：每轮仍出 1 张，依靠克制、历史组合、局势规则和身份被动形成策略。

备选方案：每场允许一次双牌回应。只有单卡原型被试玩证明过浅时再启用。

### 2. 起手身份名称与数量

默认首版为名校毕业生、普通大学毕业生、职校技术员、厂区熟练工、灵活就业者。灵活就业者指外卖员、快递员、网约车司机等平台接单或弹性排班职业，不是自学转行或临时待业的统称。需要继续检查五种身份是否覆盖足够多的现实起点，同时避免把学历当成人生排名。

### 3. 中学分流的现实程度

需要确定分流更多反映考试与家庭资源，还是更多保留玩家主动选择。默认采用“现实条件影响机会，关键选择影响是否抓住机会”，不允许纯随机决定。

### 4. 童年余温的强度

默认每场一次：召回一张牌并降低 1 点压力。需要试玩验证它是否过强，以及是否应该由某些温暖记忆强化，而不是所有牌效果完全相同。

### 5. 成年应对组调整频率

默认在每场困局之间允许重组 8 张牌。若玩家频繁针对下一场换成唯一最优解，可改为每两个章节或付出叙事代价后调整。
