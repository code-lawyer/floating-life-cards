# v2 技术迁移计划

## 当前边界

当前 v1 已具备可复现随机数、单一规则 reducer、永久卡牌集合、跨困局重新洗牌、版本化存档和可选叙事裁判。v2 应复用这些稳定接缝，不重写整个项目。

主要变化集中在：

- 成长事件从固定年龄表变为条件候选池。
- 增加成长路线、故事标记和成年起手身份。
- 成年开始前加入时间跳切总结。
- 弃牌语义调整为回忆堆。
- 加入每场一次童年余温。
- 应对组允许在成年章节之间调整。

## 目标领域状态

GameState 需要新增或明确以下概念：

- growthRoute：当前成长路线及形成原因。
- storyFlags：会影响后续事件和身份的关键选择标记。
- encounteredGrowthEvents：避免同一人生重复抽到同一事件。
- startingIdentity：时间跳切后生成的成年起手身份。
- adultDeck：当前 8 张应对组。
- EncounterState.warmthUsed：当前困局是否已使用童年余温。

记忆牌继续使用稳定 ID，并保留来源年龄、标签和原始记忆文本。起手身份和成长路线使用内容 ID，而不是把整份内容对象复制进存档。

属性体系的目标规则见 [ATTRIBUTE_SYSTEM.md](./ATTRIBUTE_SYSTEM.md)。代码只持久化三项成长倾向、四项资源、记忆牌和故事标记；五类成长画像在需要时从记忆牌标签派生，不能再保存一份可能与牌册失去同步的独立计数。

## 内容数据边界

成长事件数据需要支持：

- 最小与最大年龄。
- 允许的成长路线。
- 必需和排除的故事标记。
- 抽取权重。
- 选择产生的标签、资源和标记。
- 可选的后续事件 ID。

规则模块负责检查条件、权重抽取和确定性；内容模块只声明数据，不能执行任意函数。

## 状态机调整

建议目标阶段：

1. title
2. origin
3. growth
4. growth-result
5. growth-summary
6. time-skip
7. deck
8. encounter
9. encounter-result
10. adult-event
11. adult-result
12. ending

growth-summary 展示童年牌册、成长倾向和路线；time-skip 生成并解释起手身份。两页都不引入新的年度模拟。

## 模块整理

在扩大内容前，将现有大文件按边界拆分：

- game/content/growth.ts：童年事件与选择。
- game/content/identities.ts：成长路线和起手身份。
- game/content/encounters.ts：成年困局。
- game/content/adult-events.ts：困局之间的成年选择。
- game/rules/growth.ts：事件候选与阶段去向。
- game/rules/encounter.ts：出牌、回忆堆与童年余温。
- screens/：按阶段拆分 React 页面。

顶层 game.ts 继续提供单一 reducer 和少量查询函数，React 不直接计算规则。

## 存档策略

成年原型加入显式的故事/原型运行模式后，当前存档已升级为 `version: 5`：正式故事使用 `floating-life-cards.save.v5`，原型使用绑定当前包版本的 `floating-life-cards.prototype.v5`。两者不会互读或互相覆盖，也不会把旧构建原型误报成新构建试玩证据；v4正式故事可迁移并补齐成年身份，旧原型不迁移。

身份和内容引用必须在加载时验证 ID 是否仍存在。仅检查版本、seed 和 cards 数组不足以支持未来内容调整。

## 测试要求

必须新增：

- 相同种子与行动仍生成相同事件分支和身份。
- 事件候选遵守年龄、路线与标记条件。
- 三种中学路线都能进入至少两种成年身份。
- 记忆牌在困局之间完整恢复。
- 童年余温每场只能使用一次，并能召回回忆堆中的牌。
- 起手身份被动只在声明的条件下生效。
- 普通成长属性能够完整走到五场结局，不依赖测试作弊数值。
- 完整流程在移动视口和键盘操作下可完成。

建议增加一个无界面模拟入口，统计不同种子下身份分布、章节胜率、心气耗尽率和各类牌使用率。模拟用于发现明显失衡，不代替真人试玩。

## 暂不修改

- LLM 裁判仍只返回叙述文本。
- 本地可复现 RNG 继续作为唯一随机源。
- 资源上限和三角克制先保持现状。
- 不接入账户、云存档、排行榜和在线经济。
